# Guest adds an Audi TT to Garage

## Статус

Draft за вимогою `requirements/add-car-audi-tt.md`; UI-ознаки та результат картки ще потрібно підтвердити за поточним UI.

## Передумови

- Відкрити QAuto через `baseURL` та увійти натисканням `Guest log in`.
- Переконатися, що відкрита Garage (`/panel/garage`) і доступна дія `Add car`.
- Виконувати додавання у гостьовій сесії; зміни тимчасові.

## Сценарій

1. Відкрити форму `Add a car` дією `Add car`.
2. У Brand обрати `Audi`.
3. Після доступності залежного списку Model обрати `TT`.
4. У Mileage ввести `12000` km.
5. Натиснути `Add`.

## Очікуваний результат

- Форма `Add a car` закривається.
- У Garage з'являється запис автомобіля для щойно доданого Audi TT.
- Запис показує Mileage `12000` km.

## Обсяг

Один UI-сценарій: додавання та перевірка відображення авто у Garage. Без редагування/видалення, Fuel expenses, API-викликів чи перевірки збереження після завершення guest-сесії.

## Locator та oracle evidence

- Використовувати лише ролі, accessible names, labels або test IDs, підтверджені поточним accessibility snapshot/locator picker.
- Скріншот `requirements/addcar.png` підтверджує тільки структуру й заповнення форми до натискання `Add`; він не підтверджує locators, успішне збереження або вигляд картки.
- До запуску сценарію уточнити за UI точний текст/ознаку картки та відображення пробігу. Не вигадувати assertion для них.
- Якщо Audi/TT недоступні, форма не закривається, або запис не з'являється/не можна однозначно ідентифікувати його, зафіксувати фактичний blocker замість припущення про успіх.
